Panel UI

ui.set

set(widgetId, value) : boolean

Arguments: Panel widget ID and runtime value

Measurement Result: numeric ui.set evaluates configured min/max inclusive, {reset:true} clears. Measurement Table: array of {name,value,unit,low,high}, or {reset:true}. Event Log: {append:{level,message,source?,timestamp?}}, {append:[entries...]}, full array to replace, or {clear:true}. Levels: DEBUG,INFO,PASS,WARN,FAIL,ERROR. GUI filter/Copy/Clear/Export CSV; timestamps default to local time; maxEntries bounds history, live entries not saved. Test Sequence: array of unique {id,name,description?,status?,message?,elapsedMs?} (maxSteps property), {update:{id,status?,message?,elapsedMs?,name?,description?}}, {reset:true} (retain steps, reset states), or {clear:true}. States: pending,running,pass,done,fail,error,skipped,aborted. The Test Sequence is a VIEW; the native TestRunner (if used) owns scheduling, statuses, deadlines and results. Direct ui.set() can still update a standalone sequence widget without TestRunner. Invalid updates are ignored atomically and logged to Qt warnings. ui.set confirms a known widget ID, not per-widget payload validation. Conversion from JS objects to native Qt values occurs on the script thread. Hidden Pages are updated; runtime values are NOT persisted to .wfpanel. See Examples > Getting Started > Automated Test Station.

ui.set("resultPositive",3.301);
ui.set("stationSequence",[{id:"power",name:"Check V+",status:"pending"}]);
ui.set("stationSequence",{update:{id:"power",status:"pass",elapsedMs:125,message:"3.301 V"}});
ui.set("stationLog",{append:{level:"PASS",message:"Power verified",source:"Station"}});

ui.get

get(widgetId) : value

Arguments: Panel widget ID

Returns standard JavaScript primitives, arrays and plain objects (including true nested Array rows for Experiment Data Tables). No Qt QVariantList conversion is necessary: Array.isArray(ui.get("recipeTable")) is true. A returned array/object is a snapshot; call ui.set() to commit changes. Reads the most recently assigned value from the persistent Panel runtime, even when the widget is on a hidden Page. Test Sequence initially returns its configured pending steps; subsequent ui.get reads the last payload sent to ui.set, not a merged or evaluated full sequence snapshot. Measurement Result starts as null; Measurement Table and Event Log start as empty arrays. ui.get(eventLogId) returns the last ui.set payload, not the complete accumulated log or any rows cleared from the GUI. For complete examples, open Examples > Getting Started > Automated Test Station.

var setting = ui.get("speed");

on(widgetName, eventName, callback)

Arguments: Panel widget, event, callback

Panel-only scripting event subscription. Use the exact saved event name (for example, clicked or valueChanged); a button uses clicked, not click. Alternatively configure handlers in the visual Events editor.

ui.on('startButton','clicked', function(){ print('Start'); });

Panel Data

Data.get

get(name) : number|boolean|string

Arguments: Declared Panel Data name

Project-owned shared variables span all Pages. Unknown name throws. Values reset to saved initial defaults each Run; no automatic hardware operation or disk logging.

const speed=Data.get('Motor.ActualRPM');

Data.set

set(name,value) : boolean

Arguments: Declared name and value matching Number/Boolean/Text type

Automatically refreshes every compatible Value-bound widget on all Pages, without triggering a user event. Invalid type or missing name throws. Direct ui.set on a bound widget throws; for unbound widgets ui.set is unchanged.

Data.set('Motor.ActualRPM',1250);

Data.names

names() : string[]

Arguments: No arguments

Lists variables defined under Properties → Panel Data, not files in the shared PanelData directory. Design-time initial values and live Run values are separate.

print(Data.names().join(', '));

Data.onChange

onChange(name,callback,{immediate?:boolean}) : number

Arguments: Declared variable name, function(value,previousValue,name), optional immediate

Fires synchronously after successful, changed Data.set or compatible operator Value Binding edits. No notification for equal writes, initial project defaults, or invalid values. immediate:true invokes once on registration with previousValue undefined. Listeners may call Data.set; queued delivery avoids recursive stack growth and caps a feedback cycle at 256 events. Throws for invalid arguments or when 256 listeners are active. Callback errors appear in Panel diagnostics without stopping other subscribers. Returns an integer subscription ID valid until Stop.

const watcher=Data.onChange('Motor.ActualRPM',function(value,previous,name){ print(name,previous,'->',value); },{immediate:true});

Data.offChange

offChange(subscriptionId) : boolean

Arguments: Numeric subscription ID from Data.onChange

Removes a previously registered listener. Returns true only once; false for unknown/removed IDs. Subscriptions are cleared automatically when the Panel stops. No physical outputs or I/O occur automatically.

Data.offChange(watcher);

Data.computed

computed(name, dependencies, formula) : string

Arguments: Predeclared target variable; array of 1..16 declared dependency names; pure function(...values)

Registers one typed, read-only runtime formula. Recomputes synchronously in topological order when any declared dependency changes, including bound operator inputs. Values propagate to bound displays and Data.onChange; source listeners see updated derived values. Dependencies must be explicit; formulas cannot call Data.set or register additional computed values. Up to 64 formulas. Duplicate targets, missing dependencies, editable output bindings and dependency cycles are rejected. Formula exceptions/invalid outputs are reported; previous derived values are retained. All computed definitions reset on Stop.

// Declare Motor.TargetRPS as Number in Properties → Panel Data first.
Data.computed('Motor.TargetRPS',['Motor.TargetRPM'],function(rpm){return rpm/60;});

Data.isComputed

isComputed(name) : boolean

Arguments: Declared variable name

Returns true if Data.computed registered the declared variable for this Panel run. Computed values are read-only via Data.set and native input. Unknown names throw. All definitions must still exist in Properties → Panel Data to allow design-time widget binding.

print(Data.isComputed('Motor.TargetRPS'));

Timers

setTimeout

setTimeout(callback, milliseconds, ...args) : integer

Arguments: Callable function; integer delay 10..86400000 ms; optional callback arguments Units: ms

Panel scripts only. Schedules one callback; removed from active timers before invocation. Uses Qt event-loop timing; no guaranteed execution deadline. Does not block onInitialize() or other scripts. An invalid delay throws a script error.

setTimeout(function(message){print(message);}, 500, 'ready');

clearTimeout

clearTimeout(timerId) : void

Arguments: Timer ID returned by setTimeout(); an unknown ID is harmless

Cancels an outstanding one-shot timer. Safe when called after it has already fired. Automatic cleanup prevents callbacks after Panel stop and restart.

const id=setTimeout(function(){print('late');},2000);
clearTimeout(id);

setInterval

setInterval(callback, milliseconds, ...args) : integer

Arguments: Callable function; integer interval 10..86400000 ms; optional callback arguments Units: ms

Panel scripts only. A native Qt QTimer on the PanelRuntime/QJSEngine thread schedules repeat callbacks; each call creates an independent timer. At most 256 active timers. No overlap: long synchronous JavaScript delays this timer, UART polling and TestRunner. Invalid delays and over-capacity requests throw script errors. Not a real-time clock.

let id = setInterval(function(){ ui.set('counter',Number(ui.get('counter'))+1); }, 250);
// Later: clearInterval(id);

clearInterval

clearInterval(timerId) : void

Arguments: Timer ID returned by setInterval(); an unknown ID is harmless

Cancels a repeating timer immediately; can be called inside its callback. All timers are cancelled when the Panel stops. Cancelled IDs are not reused in the same Panel run.

const id=setInterval(function(){print('tick');},1000);
clearInterval(id);

Digital patterns

Patterns1.runSequence

runSequence(pins, bitStrings, bitRateHz) : boolean

Arguments: 1..3 distinct DIO pins; 2..1024 bits/channel; 10..1,000,000 logical bits/s Units: bits/s

WFScript-specific extension, not a native WaveForms script method. The first character in each string is generated first, all strings must contain only 0/1 and be equal length. One shared DigitalOut start and divider keep channels aligned. Repeats continuously until stop(); SDK range and buffer limits are discovered at runtime. All output pins return to high-Z on stop. For tests connect DIO0->DIO3, DIO1->DIO4, DIO2->DIO5 through separate 1k resistors.

if(!Patterns1.runSequence([0,1,2],["01010101","00110011","00001111"],1000)) throw Error(Patterns1.lastError);

Patterns1.configSequence

configSequence(pins, bitStrings, bitRateHz) : boolean

Arguments: Same arguments as runSequence Units: bits/s

Configure repeating multi-pin custom DigitalOut buffers but do not start them. Call runSequence to start. Stop releases owned outputs to high impedance.
